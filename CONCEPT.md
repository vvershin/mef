# CONCEPT.md — концепция решения

Этот файл — источник истины по архитектуре и концепции. Любая задача начинается со сверки с ним; изменения концепции фиксируются здесь после согласования с владельцем.

## 1. Существующая архитектура (базовая линия)

Serverless-система без бэкенда и БД:

```
admin/ (React+Vite, localhost:5173)          miniapp/ (React+Vite, Telegram Mini App)
  │ редактирует данные в localStorage          │ читает JSON с GitHub Pages
  │ публикует docs/*.json через GitHub API     │ кэширует в localStorage
  └──────────────┬─────────────────────────────┘
                 ▼
        docs/{events,places,other-cities}.json  ← «база данных»
                 ▼  (git push / GitHub Contents API → main)
        GitHub Actions (deploy.yml) → miniapp/dist + docs/*.json → GitHub Pages
                 ▼
        https://vvershin.github.io/mef/  → пользователи в Telegram
```

Общая схема данных: `shared/types.ts` (`Event`, `EventsDatabase` и т.д.).

## 2. Расширение: конвейер сбора событий

Добавляем автоматический сбор мероприятий с внешних сайтов и ручную модерацию перед публикацией.

```
[1] Агент-скаут (OpenCode)                [2] Отчет          [3] Админка: вкладка «Импорт»      [4] Публикация
    сканирует сайты из конфига    →    reports/*.json   →    загрузка, редактирование,    →    a) docs/events.json → GitHub → Pages → miniapp
    фильтрует по темам/ключевым словам                      удаление ненужных                b) сообщение в Telegram через бота подписчику
```

### 2.1. Агент-скаут (event scout)

- Кастомный **агент OpenCode** `scout` — определение `.opencode/agents/scout.md` (промт/правила), конфиг `scout.config.json` (сайты/тема/ключевые слова). Оба файла в репозитории.
- Ссылка-симлинк `/Users/vvershin/tgAdmin/.opencode/agents/scout.md` → файл в репозитории нужна для обнаружения агента, когда сессия запущена в родительском каталоге; канонический файл — в репозитории.
- Запуск: `opencode run --agent scout` из корня репозитория или через сабагента `scout` из основной сессии.
- Ограничения поведения заданы в промте агента (писать только в `reports/**`, не публиковать). Блок `permissions` в frontmatter в текущей сборке OpenCode использовать **нельзя** — он ломает агенту весь доступ к инструментам (проверено 2026-10-22).
- Логика: обходит сайты, находит **будущие** мероприятия, соответствующие темам/ключевым словам (при сомнении — включает, модерацию делает человек).
- Выход: файл отчета в `reports/` с датой запуска в имени + `siteNotes` по каждому сайту.

### 2.2. Формат отчета — JSON

Схема полей повторяет `Event` из `shared/types.ts` (чтобы импорт не требовал сложных преобразований) и добавляет поля происхождения:

```jsonc
{
  "generatedAt": "2026-10-22T12:00:00Z",
  "scoutConfig": "scout.config.json",   // ссылка на конфиг запуска
  "events": [
    {
      "title": "Концерт ...",            // обязательно
      "date": "YYYY-MM-DD",              // обязательно, только будущее
      "time": "HH:mm",
      "endDate": "YYYY-MM-DD",
      "location": "Название площадки",
      "address": "Адрес",
      "url": "https://...",              // обязательно: ссылка на событие
      "sourceUrl": "https://...",        // страница, на которой найдено
      "category": "music",               // значение EventCategory, если удалось определить
      "price": "500 ₽",
      "isFree": false,
      "description": "...",
      "organizer": "...",
      "imageUrl": "https://..."
    }
  ]
}
```

При выгрузке в `docs/events.json`: `url` → `registrationUrl`; `id`, `createdAt`, `updatedAt` генерируются админкой; дубликат = совпадение даты и (`url` или названия) — одинаковый `url` на разные даты это серия, не дубль.

### 2.3. Админка: вкладка «Импорт отчета»

Реализована: `admin/src/components/ScoutImportTab.tsx` + `admin/src/utils/scoutImport.ts`.

1. Загрузка файла отчета агента (JSON из `reports/`) с валидацией схемы.
2. Записи, уже существующие в базе (дубль: та же дата и `url`/название), **в окно импорта не попадают** — число пропущенных показывается в шапке; в списке только новые.
3. Таблица модерации: чекбокс «в выгрузку», ✏️ редактирование всех полей (переиспользуется `EventEditor`), 🗑 удаление строк.
4. Кнопка «Выгрузить в базу»: объединяет отмодерированные события с базой мероприятий (localStorage, далее стандартный экспорт); слияние дополнительно подстраховывает от дублей (например, если правка сделала запись дублем), итог сортируется по дате. Публикация `events.json` — существующей кнопкой GitHub → Опубликовать на вкладке «Мероприятия».

### 2.4. Рассылка в Telegram

Реализовано: `admin/src/utils/telegram.ts` + `TelegramSettingsModal.tsx`, кнопка «✨ В Telegram» во вкладке «Импорт отчета».

- Формат «la semaine française» (образец владельца от 2026-10-22): шапка → дни по-французски (`lundi, 19 octobre`) → события маркером ✨ → «le week-end français» перед выходными → подпись «bonne semaine ✨».
- Ссылки — **HTML-гиперссылки на названии события** (`parse_mode: HTML`), без URL текстом.
- Период: календарная неделя (Пн–Вс) от даты отправки; пустые дни не показываются; отправка сразу, без предпросмотра (решение владельца).
- Отправка напрямую из браузера через Bot API (`api.telegram.org/bot<token>/sendMessage`); токен бота и chat_id подписчика — в настройках админки (localStorage `telegram_settings`): кнопка ⚙ на вкладке «Импорт отчета» (есть и без загруженного отчета) либо автоматически при первом клике «✨ В Telegram».
- Сообщение длиннее 4096 символов автоматически разбивается на несколько (по строкам, заголовок дня остается с первым событием).

## 3. Границы и принципы

- Система остается serverless: без своего бэкенда и БД; внешний «бэкенд» — GitHub (API, Actions, Pages) и Telegram Bot API.
- Публикация данных — только через существующий механизм `docs/*.json` → GitHub Pages; формат `shared/types.ts` меняется только с сохранением совместимости с уже опубликованными данными.
- Новый код админки — в стиле существующего (React + Tailwind, localStorage, ручная публикация), без новых зависимостей без необходимости.
- Отчеты агента — артефакты в `reports/`, версонируются в git (история сбора).

## 4. Принятые решения (владелец, 2026-10-22)

1. Агент-скаут — кастомный агент OpenCode, конфиг и определение в репозитории.
2. Формат отчета — JSON (схема в п. 2.2).
3. Кнопка «Выгрузить в базу» объединяет отмодерированный отчет с существующими мероприятиями; дубликат = та же дата и тот же `url` или название (серия с тем же `url` на новую дату добавляется как отдельное событие).
4. Отправка Telegram-сообщения — напрямую из админки через Bot API; токен и chat_id в настройках админки.

Открытый вопрос (не блокирует этапы 2–5): точный формат Telegram-сообщения — согласуется на этапе 6.
